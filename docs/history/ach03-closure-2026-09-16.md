# ACH-03 closure — 2026-09-16

ACH-03 completes the curated achievement showcase built on PROF-07. Owners can
now mix current personal records, earned milestone medals and one attained
Renaissance rank in the same ordered six-slot profile ledger.

## Product behavior

- Settings loads the authoritative achievements response alongside the
  existing record and featured-selection reads.
- Every earned milestone is eligible. The rank list contains the stable ladder
  only through the owner's current non-regressing rank, never a future title.
- Records, achievements and the one permitted rank share the same six slots,
  ordering controls and single save action.
- Selected rows retain exact live labels and achievement provenance. Unknown or
  stale references remain removable in Settings but are omitted from profile
  reads by the backend.
- Records follow Personal Records privacy. Milestones and rank titles follow
  Achievements privacy on authenticated and signed-out profile reads.

## Delivery

- Contracts: no change was required. The consumers remain on
  `@sunsteel/contracts@0.44.0`, whose discriminated featured-item request and
  response types already include `ACHIEVEMENT` and `RANK`. Commit `3824508` and
  npm registry integrity were reverified before implementation.
- Backend: the PROF-07 service already validates achievements from live
  `ACHIEVEMENT_UNLOCKED` events, accepts stable ranks only through the current
  non-regressing rank, limits the list to six with at most one rank, and
  resolves reads after achievements authorization. ACH-03 adds explicit
  acceptance/rejection coverage and aligns the agent documentation; no
  production code, migration or deployment configuration changed. Commit
  `62329ab`; Backend CI run 35141525337 passed both Node 22 checks and analytics
  integration. Railway deployed successfully and the production health endpoint
  returned 200.
- Frontend: the featured Settings card now presents current records, earned
  medals and reached ranks with shared slot guards, exact selected-item
  presentation and accessible controls. The profile empty-state copy reflects
  all three kinds. Commit `230298f`; Frontend CI run 35141537493 and Vercel
  production deployment 6488932579 passed.

## Verification

The isolated backend gate passed lint, types, 174 tests, build and compiled
module import. The isolated frontend gate passed lock validation, lint, types,
334 tests across 58 files and a production build. No build ran in the owner's
active checkout or against its running development server.

An authenticated reversible browser flow used the real local frontend and
backend. The owner began with no featured items; Settings added the earned
`First Record` medal and the attained `Artisan` rank, the replacement request
returned 200, and the profile rendered both rows with achievement provenance.
There were no console errors. The exact original empty selection was then
restored through the authenticated endpoint and compared structurally.

The profile layout passed 14/14 regression cases and Settings passed 14/14
across both themes and every relevant exact boundary width. Three Settings cases
initially met local backend transaction expirations and passed on a fresh,
isolated rerun.

The complete 409-case `ui:regression` sweep did not complete. Repeated sustained
runs caused unrelated `/achievements` and workout-progress reads to return 500
when the local backend's Prisma interactive transaction exceeded its five-second
window; a concurrent local workout writer also appeared in the backend log. The
production CI/builds, deployments and every affected profile/Settings case are
green, but this full-suite result is deliberately not recorded as a pass.

## Not verified
