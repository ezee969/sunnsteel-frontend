# Translating Sunnsteel

How every screen gets its Spanish, so that the translation passes (`I18N-03` to
`I18N-05`) read as one product. The foundation is `I18N-01`; see the
Translations note under Gotchas in `CLAUDE.md` for how a request picks its
language.

## Rules

1. **English does not change.** Every English string keeps its exact text,
   punctuation and casing, so the existing tests, the regression sweep and the
   portfolio captures keep passing. Moving a string into `messages/en/*.json`
   must be a move, never an edit.
2. **Only product text is translated.** Never what a member wrote (routine,
   day and exercise names they typed, notes, comments, biographies), never a
   username, never an API value.
3. **Stored values never change.** Enum values, ids, query parameters, URL
   segments, `localStorage` keys and catalog names stay as they are; a label is
   looked up from them.
4. **One namespace per area**, one file per area and language:
   `messages/en/<area>.json` and `messages/es/<area>.json`, registered in
   `messages/index.ts` under the same key. Keys are camelCase and grouped by
   component or module (`workout.restTimer.skip`).
5. **Components** call `useTranslations('<area>.<group>')`. **Pure copy
   functions** (`lib/utils/*`) take a `t: Translator<'<area>.<group>'>`
   argument from `@/i18n/translator` instead of returning English, and callers
   pass their own `useTranslations(...)`. Never import `MESSAGES` outside tests
   and `i18n/`.
6. **Tests run in both languages.** Replace English expectations' inputs with
   `translatorFor('en', ns)`, keep the English expectations unchanged, and add
   Spanish assertions for the cases that carry a rule. A test that guards copy
   (no cause, no advice, no imperative, no promised timetable, no "missed")
   must also run over the Spanish messages with a Spanish word list.
7. **Plurals and variables use ICU**, never string concatenation:
   `{count, plural, one {# serie} other {# series}}`. Both languages must read
   the same arguments; `messages.test.ts` enforces it.
8. **Dates and numbers** follow the language. In a component,
   `const locale = useLocale()`; then `dateFormatter(locale, options)` or
   `intlLocale(locale)` for `toLocale*String`/`Intl.*`, and
   `dateFnsLocale(locale)` for `date-fns` `format`. A pure function takes
   `locale: Locale`. English stays `en-US`. Weekday and month names that a
   module hard-codes in English become messages or `Intl`.
9. **Text built outside this repo stays as it is, and is listed.** Strings
   produced by `@sunsteel/contracts` helpers (`routineDayLabel`'s "Day A",
   `exerciseGroupLabel`'s "Superset A1", validation problems) and messages
   returned by the API are not edited here. Where a frontend equivalent is
   simple (a label from a stable code or index), build it with a message key;
   otherwise leave it and name it in the closure for `I18N-06`/`I18N-07`.
   Catalog exercise names, muscles, equipment, patterns, achievement titles
   and rank titles belong to `I18N-07`.
10. **Accessible names, `title`, `alt`, placeholders, toasts and
    confirmation dialogs** are text too.
11. **Spanish is about 20-30% longer.** Check a translated page at 320 and 390
    in Spanish; prefer a shorter phrasing to a truncation.

## Voice

Neutral Latin American Spanish, addressed with *tú* ("Revisa tu conexión").
Sentence case, as in English. Keep the product's plain, factual tone: state
what happened, do not cheer or scold. Buttons are infinitives ("Guardar",
"Empezar", "Cancelar"); an instruction in running text uses *tú* ("Elige un
día").
