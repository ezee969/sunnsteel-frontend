# UI proof-of-concept review — prioritised issues

1. **P0 · Pass A/B — Crimson fails as the action colour on this screen.** The completed session presents a large crimson “Finish Session” control and repeats the same red family across every checked set. In the after screenshots this reads as a page full of errors or destructive controls, not successful completion; in the incomplete-session dialog the same treatment makes “Finish Session” look explicitly dangerous. The before state’s green completion language did not create this ambiguity. The central v0.1 decision should not advance unchanged.

2. **P0 · Pass A/B — Editable set fields lose their affordance in light mode.** Reps, weight, and RPE values visually float inside one beige strip with no clear individual input boundaries, so the primary interaction reads like a read-only ledger. The before screenshots made each editable field explicit. Dark mode still shows three inset wells, creating a theme-dependent component model rather than one consistent control.

3. **P0 · Pass A — Light-mode supporting text is not viable at the rendered sizes.** `TARGET`, `OPTIONAL`, RIR, `LAST TIME`, and previous-performance values are thin, tightly tracked, and too close to their surfaces. On the 390px screenshots several are functionally caption-sized texture rather than readable information. The typography compounds the already identified token contrast defect.

4. **P1 · Pass A — Gold has no usable semantic hierarchy.** Gold marks progress, set numbers, exercise status, completion, record/improvement, active rules, and warnings. “COMPLETE,” “IMPROVEMENT,” and “1 set remaining” therefore share essentially the same visual voice even though they represent success, reward, and risk. The warning in the finish dialog directly undermines the claim that gold means earned honour.

5. **P1 · Pass B — The routine title regresses responsively.** At 390px, the before screenshot shows “UPPER / LOWER - AUTUMN BLOCK” in full while the after screenshot truncates it to “UPPER / LOWER -…”. At 768px the regression is more severe: the after state reduces the title to “UPPER /…”. Cinzel’s tracking and the fixed summary block consume too much width for this masthead.

6. **P1 · Pass B — Completion state becomes less explicit and less scannable.** “3/3 sets completed” is shortened to “3/3 sets,” checkmarked completion pills become bare “COMPLETE” labels, and completed groups lose the green success surface used before. In a dense workout, completion is now carried mainly by a thin gold rule and a red checkbox—the two colours with the most ambiguous meanings in the new system.

7. **P1 · Pass A — The 1440px set layout expands instead of becoming more informative.** Three small numeric values are stretched across almost the full 1200px ledger, leaving hundreds of pixels of dead horizontal space between related labels and values. The layout needs bounded field widths or a compact data cluster; otherwise the “open ledger” is tablet geometry enlarged for desktop.

8. **P1 · Pass A — The mobile dialog behaves like an accidental edge-to-edge sheet.** At 390px it touches both viewport edges despite retaining dialog radius and shadow, but it has none of the structural cues of a sheet. Its title is left-aligned, the question and note copy are centred, the progress details return to left alignment, and the primary/cancel actions switch from a horizontal desktop order to full-width stacking. The result lacks a stable reading axis and makes the risky action disproportionately dominant.

9. **P1 · Pass A — Completion information is repeated without establishing priority.** The 390px screen shows `COMPLETE 100%`, `SETS 15/15`, another `PROGRESS 100%`, a full gold bar, per-exercise `COMPLETE`, and checked sets. This repetition crowds the masthead and action panel while adding no decision-relevant information.

10. **P2 · Pass A — The type system is over-applied at the micro level.** Widely tracked uppercase labels appear in the masthead, progress panel, every set, every target, every previous-performance row, and every status. Combined with Cinzel, Oswald, and Space Mono in a small area, hierarchy is expressed through constant stylistic switching rather than clear scale and spacing. At 390px the repeated micro-caps create visual chatter around the values users need during a workout.

11. **P2 · Pass A — Dark mode retains a box-within-box pattern that the direction claims to remove.** Each set is a dark band containing three darker input wells, vertical separators, a previous-performance sub-row, and multiple horizontal rules. Exercise headers add another tonal band. The density is lower than before, but the nested surface treatment still reads as a component stack rather than a clean ruled ledger, and it does not match the flatter light-mode treatment.

12. **P2 · Pass A — The action panel is visually detached from the working content.** A bordered panel with generous padding, a full-width progress bar, and an oversized full-width CTA sits above much tighter exercise rows. At desktop widths it becomes the largest object on the page despite representing a terminal action, producing the familiar generic dashboard pattern of “metric card plus giant button” rather than an integrated workout control.

13. **P2 · Pass A — The status-marker logic is visually unexplained.** Every completed set receives a gold left rule, but only the final “Hanging Leg Raise” group receives a full-height outer gold rule. Because all five exercises are marked `COMPLETE`, that unique group marker looks like a stale focus/current-exercise state rather than completion or honour.

14. **P2 · Pass B — Mobile loses elapsed-time precision.** The before 390px header includes seconds; the after 390px header drops them while the 768px and 1440px variants retain them. That is a content change introduced only at the smallest breakpoint, not a necessary reflow of the same information.

15. **P2 · Pass A — The restyle shows a generic AI-theme-pass signature.** The same recipe—condensed uppercase label, gold accent, hairline rule, beige/black well—is applied to nearly every semantic layer regardless of whether it is navigation, editable data, completion, warning, or history. The finish dialog repeats the familiar “stacked tinted cards inside a modal” composition. The result looks token-generated because the visual treatment is more consistent than the interaction semantics.
